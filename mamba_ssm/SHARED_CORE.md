# Shared Mamba implementation

All paper experiments import this `mamba_ssm` package. Install from the
`papercode` directory with `python -m pip install -e . --no-build-isolation`
after installing a suitable CUDA-enabled PyTorch environment, or put
`papercode` first on `PYTHONPATH`. The business directories are source entry
points and do not carry independently installable model packages.

The package retains Mamba-1/2, Mamba-3 SISO/MIMO, generalized-J and second-order
variants, and Triton, TileLang and optional CuTe implementations. Mamba-3 does
not need the Mamba-1 `selective_scan_cuda` extension. To build that optional
extension from the shared `csrc` sources, install with
`MAMBA_KEEP_CUDA_BUILD=TRUE python -m pip install -e . --no-build-isolation`.
This requires a compatible CUDA/ROCm compiler; the default installation skips
that build. Both installation paths use the local research sources.

## Consolidated behavior

Before consolidation, the repository implementation, state-tracking copy,
and all four intervention copies had identical hashes for all 58 Python
files. They form the shared baseline. Pretraining had nine modified files
and lacked four reference/second-order modules. Its additional capabilities
are merged here:

- Lazy public imports and lazy Mamba-1/2 selection avoid requiring
  `selective_scan_cuda` when selecting Mamba-3.
- Non-reentrant backbone activation checkpointing and chunked LM loss keep
  pretraining memory behavior. The loss lives in `mamba_ssm.utils.loss`, so
  the core has no dependency on pretraining scripts.
- SISO/MIMO backward functions read `ctx.saved_tensors` once, preserving
  compatibility with activation-checkpoint recomputation.
- `rope_fraction=0.0` keeps the pretraining parameter layout: no learned angle
  projection, but zero angles supplied in the usual half-RoPE kernel shape.
  It is distinct from `rope_mode="none"`, which preserves the baseline
  projection shape for state-tracking ablations and existing checkpoints.
- `_transform_projected_angles` preserves the pretraining subclass hook.
- An unavailable or incompatible optional CuTe inference backend does not
  prevent training imports; SISO retains the Triton decoding fallback.

The baseline's chunked prefill, fixed/disabled phase modes, PyTorch SISO
reference, MIMO function override, and Mamba-2 convolution override remain
available. All standard checkpoint parameter names and shapes are retained;
the zero-RoPE pretraining layout is also retained.

## Numerical scope

The shared SISO forward, backward and step kernels retain the baseline's
Triton compatibility fixes: scalar reductions replace unsupported width-one
tensor-core dot products, and TMA stores cast explicitly to descriptor dtype.
These kernels were already used by the copied intervention and state-tracking
code. Pretraining previously used the older dot/store forms, so GPU training
and decoding are not claimed to be bitwise identical after consolidation.
CPU import, parameter-layout and gradient checks cannot establish GPU
perplexity equivalence. Existing reported results remain historical results;
they have not been regenerated by this source-layout change.
